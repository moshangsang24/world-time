## 阶段 1：基准时区改为洛杉矶

### 1.1 基准时区集中到一处

在 `src/data/constants.ts` 新增：

```ts
export const BASE_ZONE = {
  timezone: 'America/Los_Angeles',
  label: '洛杉矶时间',
  cityId: 'los-angeles',
} as const;
```

所有 `'Asia/Shanghai'` 硬编码（`timeStore.ts` 4 处）改为读这个常量。以后要换基准或做成设置项，只改这一处。

### 1.2 重命名

| 旧 | 新 |
|---|---|
| `timeStore.beijingTime` | `baseTime` |
| `useTimeState().formattedBeijingTime` | `formattedBaseTime` |
| `TimeState.beijingTime`（`types/time.ts`） | `baseTime` |
| 无消费者的 `utcTime` | 删除 |

涉及 `timeStore`、`useTimeState`、`useSunPosition`、`Header`、`TimeSlider`、`WorldClock`、`WorldMap2D`。

### 1.3 界面文案

- 四处"北京时间"改为 `BASE_ZONE.label`，后面带当前时区缩写，由 `baseTime.toFormat('ZZZZ')` 得到（现在是 `PST`，夏令时期间自动变 `PDT`）。
- 默认城市列表把洛杉矶放到第一位，并在侧栏标记为"基准"；北京保留在列表里。
- `index.html` 标题、`README.md` 里的"以北京时间为基准"同步修改。

### 1.4 时间偏移语义（P1-7）

洛杉矶有夏令时，偏移必须按"经过的分钟数"算，不能按墙上时钟算。现有实现本来就是对绝对时刻做加减，这点不用改，但锚点要改：

- 新增 `anchorTime: DateTime | null`。离开实时模式的那一刻把当前时刻冻结为锚点，之后 `baseTime = anchorTime + timeOffset`，不再每次取 `DateTime.now()`。
- `toggleRealTime()` 恢复实时时把 `timeOffset` 归零、清空锚点。
- `Home` 键改为调用 `resetToRealTime()`，与 README 的描述一致。
- `useScrollControl` 的 handler 改用 `useTimeStore.getState()` 读最新偏移，effect 不再依赖 `timeOffset`，解决快速滚动丢步和反复重绑监听。

### 1.5 模块级定时器（P2-5）

保留模块级启动，加 `import.meta.hot.dispose` 清理 interval，避免热更新后叠加。

## 阶段 2：修正太阳位置

### 2.1 直射点经度（P0-1）

沿用现有 NOAA 公式，补上均时差：

```
EoT(分钟) = 4 × deg( y·sin2L₀ − 2e·sinM + 4e·y·sinM·cos2L₀ − ½y²·sin4L₀ − 1.25e²·sin2M )
    其中 y = tan²(ε/2)，L₀ 为平黄经，M 为平近点角，e 为偏心率
直射点经度 = normalize( −15 × (UTC小时 − 12) − EoT/4 )
```

`L₀`、`M`、`e`、`ε` 在 `calculateSunPosition` 里都已经算好，只需新增 EoT 一步，并替换第 40 行。赤纬不动。

`SunPosition.hourAngle` / `azimuth` / `altitude` 三个字段目前是"赤道 0° 处"的值，没有物理意义也没人用，从类型里删掉。

### 2.2 晨昏线（P1-4）

`calculateDayNightBoundary` 现在用 `atan2(-cosH, tanδ)`，象限是错的，且 δ→0 时退化。改为：

```
lat(lng) = atan( −cos(lng − 直射点经度) / tan δ )
```

`|δ| < 0.01°` 时钳到 ±0.01°，避免除零（此时晨昏线近似两条经线，结果仍然正确）。这个函数只用来画晨昏线那一条线；夜面填充用 3.3 的逐格算法，不依赖它。

### 2.3 昼夜数据源统一（P1-1）

- 把 `isDaytime` 的计算下沉到 `timeStore.updateCityTimes()`：每次更新算一次太阳位置，对每个城市调 `SunPositionCalculator.isDaylight`。store 依赖 utils，不依赖 hook。
- `useTimeState` 不再重复计算昼夜，只做格式化。
- 这样 `WorldClock`、`WorldMap2D`、`CityTimeCard` 拿到的是同一份结果。
- `useSunPosition` 去掉无人使用的 `sunlightData` 急切计算。
- 删除 `TimeCalculator.isDaytime`（6:00–18:00 那个）。

### 2.4 测试

新增 `src/utils/sunCalculations.test.ts`：

- 问题清单里的四个时刻，直射点经度误差 < 0.5°。
- 随机 50 个时刻 × 18 个城市，`isDaylight` 与 `SunCalc.getPosition` 的高度角判断一致（阈值附近 ±0.5° 的样本跳过）。
- 2025-06-21T04:00Z：北京白天、纽约夜晚。
- 春分、秋分当天晨昏线不产生 NaN。

## 阶段 3：重画 2D 地图

### 3.1 数据源

用 Natural Earth 1:110m，通过 npm 包引入：

- `world-atlas`：`countries-110m.json`（TopoJSON，约 108 KB，gzip 后约 40 KB）
- `topojson-client`：`feature()` 取陆地多边形，`mesh()` 取国界线

直接 `import` JSON 打进包里，不需要 `public/` 和运行时请求。等距圆柱投影是线性的，自己把坐标环转成 `lineTo` 即可，不需要 `d3-geo`。数据已在 ±180° 处切开，不用处理跨日界线。

### 3.2 分层绘制

`WorldMap2D.tsx` 现在 336 行，一个 effect 画所有东西。拆成：

```
src/components/visualization/
  WorldMap2D.tsx          组件：尺寸监听、分层调度、点击命中
  map2d/
    projection.ts         经纬度 ↔ 画布坐标（唯一一份）
    drawBaseMap.ts        海洋、经纬网、陆地、国界
    drawNightShade.ts     夜面与曙暮光
    drawOverlay.ts        太阳、晨昏线、城市点与标签
```

| 层 | 内容 | 何时重绘 |
|---|---|---|
| 底图 | 海洋、经纬网、陆地、国界 | 只在尺寸或主题变化时，画到离屏 canvas 缓存 |
| 夜面 | 昼夜阴影 | 时间变化时 |
| 标注 | 太阳、晨昏线、城市 | 时间或选中城市变化时 |

每帧只做一次 `drawImage(底图)` 再叠后两层，不再每秒重画 170 多个陆地多边形（P2-1）。

### 3.3 夜面算法（P1-3）

不走"多边形填充"，改为低分辨率逐格着色：

1. 建一张 360×180 的 `ImageData`（1° 一格）。
2. 每格由直射点 `(δ, λ)` 直接算太阳高度角 `h`。
3. 按高度角给透明度：`h ≥ 0°` 全透明；`0° → −18°` 线性加深（覆盖民用、航海、天文三段曙暮光）；`h ≤ −18°` 取最大值 0.6。
4. 平滑缩放 `drawImage` 到画布大小。

64 800 格、每格一次 `asin`，单次不到 1 ms。好处是没有象限、环绕、春秋分退化这些特殊情况，曙暮光过渡也是自然的。

再用 2.2 的函数在上面描一条细的晨昏线。

### 3.4 其他修正

- 太阳画在真实直射点 `(δ, λ)`，不再固定在赤道；去掉现在那 18 条放射线，只留光晕和圆点。
- 城市点颜色用 2.3 的 `isDaytime`，与夜面同源。
- 基准城市（洛杉矶）用单独的样式标出。
- 经度标尺下方加一行各时区的当地整点时间，可选，视画面拥挤程度决定。
- **尺寸**：用 `ResizeObserver` 监听容器，尺寸变化时重设 backing store 和 DPR、重建底图缓存（P2-2）。
- **比例**：画布保持 2:1，容器比例不符时上下或左右留边，地图不拉伸。
- **主题**：底图配色分浅色 / 深色两套，跟随 `settingsStore` 主题。
- 删除 `worldMapData` 手写矩形和未使用的 `COLORS` / `useMemo` 导入。

### 3.5 验收

用 Playwright 对 dev 页面截图，检查三个固定时刻（通过临时设置偏移）：

- 洛杉矶正午：太阳在西经 118° 附近，美洲亮、亚洲暗。
- 6 月某时刻：北极圈内全亮、南极圈内全暗，晨昏线呈 S 形。
- 春分：晨昏线接近两条竖线。

## 需要你确认的三点

下面是我的默认做法，不回复就按默认执行。

1. **基准时区写死洛杉矶，还是跟随浏览器时区？** 默认写死为 `America/Los_Angeles`，集中在一个常量里。跟随浏览器的话，你出差或别人打开时基准会变。
2. **地图画不画国界？** 默认画：陆地填色 + 细国界线。只画海岸线会更干净，但城市定位感差一些。
3. **3D 代码留还是删？** 默认留着不动，只保证能编译。删掉可以去掉 `three` 等三个依赖，将来要做 3D 再加回来。
